Prototype 05 · split projection / trust boundary

Context may influence reasoning. It must not mint authority.

This prototype separates authoritative control-plane inputs from mixed-trust context before producing the checkout. The runtime and human inspector still consume one artifact, but the artifact now preserves provenance and trust class instead of flattening everything into one projection.

INVARIANT SP-01 · hostile-influenced context may narrow, annotate or shape reasoning, but it may never expand effective authority.

Authority projection
Identity, delegation, policy and approved grants determine capabilities. Mixed-trust context cannot add entries here.
Context projection
Task interpretation, retrieved text, memory and tool output remain useful to the runtime, but their provenance stays visible and separate.
This is not a claim that trust separation is novel. It is a project invariant: the checkout must not erase the distinction between data that can influence reasoning and systems that are allowed to define authority.
